# 004–007 + 003b — Curves, durations and reduced motion

- **Commit:** `8204fd8`
- **Status:** DONE

Five findings that were each one edit, applied together because they are the
same fault in different files: an animation that never states its curve, or a
duration that never passes through the app's reduced-motion wrapper.

Flutter's implicit-animation widgets default to **`Curves.linear`**. Every
site below was therefore running a constant-rate fade or crossfade — the one
timing reserved for things that genuinely move at a constant rate.

## 004 — Onboarding copy switcher

`onboarding_content_panel.dart` — `AnimatedSwitcher` had a hand-typed `450ms`
and **no `switchInCurve`**, so the switcher's own fade ran linear while the
`CurvedAnimation` inside `transitionBuilder` eased only the slide. One object,
two properties, two different clocks.

Now `AppMotion.duration(context, AppMotion.sheet)` with `switchInCurve` and
`switchOutCurve` both `AppMotion.standard`, and the slide driven by the same
already-curved `animation` rather than curving it a second time.

## 005 — Quick save auto-close delay

`quick_save_page.dart` — `Future.delayed(950ms)` after a successful save.

**First attempt was wrong, and the correction is the interesting part.** It
was cut to 420ms on the grounds that 950 exceeded the 300ms ceiling. That is
the wrong ceiling: 300ms is the budget for *motion a user is waiting on*.
Nothing is blocked here — the save is committed and the sheet leaves on its
own. This is a confirmation, and a confirmation has to be read.

The arithmetic 420 missed is that the tick does not appear instantly; it
arrives through an `AnimatedSwitcher` taking `AppMotion.normal` (220ms) to
settle. That left the finished state legible for about 200ms — under the
~250ms it takes to recognise a symbol. Technically shown, practically
invisible. Reported by the user as "it drops too fast to see".

Settled at **800ms**: 220 to arrive, ~580 still. Both this and the exit
duration are resolved *before* the wait, since the sheet can be dragged away
during it and reading a MediaQuery off a dead context is a crash nobody can
reproduce.

The auto-close also got its own exit duration. `reverseDuration` stays
`AppMotion.normal` (220ms) for every user-initiated dismissal — drag, back,
scrim — where the user has decided and is waiting. The save close is the one
exit nobody asked for, so it plays at `AppMotion.sheet` (280ms), symmetric
with its entrance.

Its `AnimatedSwitcher` was also missing `switchOutCurve`.

## 006 — Rule builder condition chip

`rule_builder_sheet.dart` — `AnimatedContainer` with no `curve`. Fill, border
colour and border width all crossfaded linearly on selection.

## 007 — Thumbnail decode fade

`asset_thumbnail_image.dart` — `AnimatedOpacity` with no `curve`, on every
thumbnail in the app. A decoded frame arriving is an entrance; entrances ease
out.

## 003b — Reduced-motion sweep

`rules_explainer.dart`, `app_bottom_nav_bar.dart`, `library_page.dart` and the
files above now resolve durations through `AppMotion.duration(context, …)`.

`rules_explainer`'s `AnimatedSize` keeps animating a layout property: an
expand/collapse is the accepted exception, because no transform can reveal
content whose height is not known in advance. Noted in the code so it is not
re-reported.
